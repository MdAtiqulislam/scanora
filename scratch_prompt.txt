====================================================
1. AUTHORITATIVE SOURCE OF TRUTH
====================================================

The following contracts are frozen:

- M03 AssetStore contract is authoritative for physical assets.
- M04 PageEditState/cache identity is authoritative for semantic edit state.
- M06 GeometryEngine is computation-only.
- M07 is the authoritative raster-processing engine.
- Raw capture is immutable source-of-truth.
- processed.jpg and thumbnail.jpg are derived/cache artifacts.
- SQLite cache metadata + physically valid derived assets together determine cache validity.
- page ID is the only page identity; never use pageIndex as identity.
- Production must use exactly ONE shared M07ProcessingEngine instance / shared processing lock.
- Default heavy processing concurrency = 1.
- Preview and final processing must use the same geometry/raster-processing semantics.
- Typed Result/AppFailure error propagation is mandatory.

====================================================
2. CACHE IDENTITY — FIX COMPLETELY
====================================================

Use ONLY the canonical M04/M07 identities:

Processed:
PageCacheIdentity.forProcessed(...)

Thumbnail:
PageCacheIdentity.forThumbnail(
  processedCacheKey,
  width,
  height,
  quality,
)

Do NOT use:

PageCacheIdentity.forState()

for processed/thumbnail cache truth.

Required behavior:

A semantic edit changes:
- corners
- crop transform
- rotation
- processing profile
- relevant output specification

=> both processed_cache_key and thumbnail_cache_key become invalid/stale.

Do NOT preserve old cache keys after an edit.

savePageEditState() must invalidate cache metadata correctly.

Remove any meaningless cache-key computation whose result is not used.

====================================================
3. markCacheCurrent() MUST VALIDATE CANONICAL IDENTITY
====================================================

markCacheCurrent() must NOT accept arbitrary non-empty strings.

Before committing:

1. Load the authoritative current page state.
2. Verify page ID.
3. Verify raw asset identity.
4. Verify edit-state/revision identity.
5. Recompute the canonical processed cache key.
6. Recompute the canonical thumbnail cache key.
7. Compare supplied keys with recomputed canonical keys.
8. Verify processed and thumbnail assets physically exist and are non-zero.
9. Commit only if all conditions match.

An arbitrary key must fail even when:
- raw identity matches
- edit state matches
- files exist.

Use typed failure.

====================================================
4. STALE COMMIT / RACE SAFETY
====================================================

Fix the TOCTOU race:

Current behavior:
check page state
-> later update DB

This is insufficient.

A stale processing request must NEVER commit cache metadata over a newer edit/raw state.

Use an atomic revision/version/conditional-update strategy.

The commit must succeed only when the page still has the same authoritative state captured when processing started.

If state changed:
- do not commit stale cache keys
- do not claim success
- do not replace authoritative cache metadata
- return an appropriate typed result/failure according to existing architecture

Test with actual concurrent stale commit.

====================================================
5. SAVE() MUST NOT OVERWRITE NEWER CACHE TRUTH
====================================================

Audit SqliteDocumentRepositoryV2.save().

Current danger:
an old ScanPage snapshot containing non-null processed/thumbnail cache keys can overwrite newer DB cache metadata.

Fix this.

Rules:

- incoming NULL cache metadata may preserve current DB metadata where explicitly required.
- stale NON-NULL cache metadata must NOT overwrite newer authoritative cache state.
- page identity must be page.id.
- pageIndex is ordering only.
- preserve existing parent/page metadata correctly.
- deleted pages must still be pruned.
- deleted page assets must still be cleaned.

Do not use SQLite REPLACE semantics where it can cause destructive parent/child behavior.

====================================================
6. AssetStore MUST BE MANDATORY FOR PRODUCTION CACHE TRUTH
====================================================

Production repository/cache validation must not have:

AssetStore?

for cache truth.

Do not use:

.valueOrNull ?? false

to silently convert infrastructure errors into "asset missing".

AssetStore failures must propagate as typed AppFailure/Result.

Similarly:

pathFor() failure must NOT silently fall back to arbitrary external rawSourcePath when canonical AssetStore storage is expected.

Production processing must use canonical AssetStore-managed raw assets.

====================================================
7. PHYSICAL CACHE VALIDITY
====================================================

A cache is valid only when:

DB processed key == canonical processed identity
AND
processed asset exists
AND
processed asset is non-zero

AND for thumbnail:

DB thumbnail key == canonical thumbnail identity
AND
thumbnail exists
AND
thumbnail is non-zero.

If a derived file is:
- missing
- zero-byte
- corrupt/unusable

=> invalidate/reprocess appropriately.

In-memory cache may optimize this but is NEVER authoritative.

External deletion must evict stale in-memory cache state.
